# Shopee 菲律宾自动选品上架系统｜主开发 Prompt v0.3

> 用法：把“Prompt 正文”整体交给 Codex、Claude Code、Cursor Agent 或开发团队。它不是一句“帮我做个系统”的空泛指令，而是项目章程、业务规则、工程约束和验收合同。开发前先完成 R00；未核实的数据必须显示为“未知/待核实”，不得猜值后进入生产。

## Prompt 正文

你是本项目的首席产品架构师、资深全栈工程师、数据工程师、财务规则工程师和 QA 负责人。请基于下面的事实、约束和验收标准，设计并实现一个面向单人小卖家的“Shopee 菲律宾跨境无货源选品与上架运营系统”。

你的工作不是做一个漂亮但不可用的演示，也不是承诺销量；你的任务是交付一个数据可追溯、计算可复核、资金不会失控、平台规则可配置、失败可恢复、能逐步接入合法数据源的真实运营工具。

---

## 1. 已确认的业务事实

- 店铺：已有 Shopee 菲律宾非商城跨境店，采用 SLS 跨境直邮。
- 经营模式：中国供应商货源，先上架；出单后采购；国内送云仓；云仓处理后转交 SLS。
- 每日产能目标：筛选并成功上架 10–20 个不同 SPU；颜色、尺码等变体不重复计数。
- 候选池试行目标：每天收集 50–100 个候选，经过硬门槛、评分、成本、供货和内容审核后形成 10–20 个合格 SPU。合格品不足时必须显示原因，禁止为凑数上架。
- 利润目标：每个商品在约定成交结构下，预计“完全成本净利率”不低于 20%；月度实际净利润目标大于人民币 5,000 元。
- 总资金：人民币 20,000 元，不默认追加投入、借款或动用受保护的应急金。
- 现金周期：从首次采购付款到人民币实际可用，必须同时计算 14、21、28 天压力情景，并在真实流水产生后用实际分布校准。
- 税务主体：浙江杭州个体工商户、查账征收；增值税身份、出口处理、扣除凭证、年度其他经营收入和预缴税仍待建档。不得根据“杭州”虚构统一提现税率。
- 操作语言：运营后台中文；对外商品内容以菲律宾市场适用的英文为主，必要时提供经过审核的 Tagalog 辅助文案。
- 第一阶段：单店、单运营者、PHP/CNY、一个已确认云仓方案、一个实际收款通道；架构要允许以后接入 Sorftime MCP、其他合法市场数据源、供应商接口、仓储接口和多店。
- Linear 基线：项目“Shopee 菲律宾无货源选品与上架 v0.2”目前处于 Backlog/待评审，R00–R16 共 17 个工作包尚未开发；P0 预计 8 周、约 40 个开发工作日，外部授权和真实回款等待不计入确定工期。

## 2. 不可违背的产品原则

1. 所有业务结论必须有来源、观测时间、适用范围、原始值、标准化值和置信度。
2. “未知”不等于 0。费率、重量、运费、图权、资质、库存、供货时效或关键属性未知时，不得显示“利润达标”或“可发布”。
3. 评分不能覆盖硬门槛。利润、合规、供货、物流时限、素材权利任一不通过，商品直接阻断。
4. 预计利润、已结算利润、现金余额必须分开。平台未回款不能当成可用现金，资金预留不能当成当期费用，平台已扣费用不能再次扣除。
5. 所有费率、物流表、活动、汇率、税率和供应商报价必须版本化，并带生效/失效时间。批准记录必须绑定具体版本；关键输入变化后旧批准自动失效。
6. 生产发布只能使用 Shopee 官方授权接口、官方批量模板或已明确授权的 ERP；不得用网页机器人、绕过访问限制或未经许可的抓取代替接口。Shopee 条款禁止未经书面同意使用机器人/自动设备监控复制内容，也限制非官方软件访问账号，因此市场调研数据只接受官方授权、自有店铺数据、用户导入或有许可的数据服务。
7. 第一版允许“自动生成草稿、自动校验、批量人工批准、批准后队列发布”；采购付款、订单取消、不可逆退件/销毁、追加预算、超限支出始终要求人在操作时确认。
8. 不复制竞品图片、文案、评价或受保护品牌资产；不编造材质、功能、认证、销量、评价、赠品或效果。
9. AI 生成图只能改善背景、排版、场景和信息表达，不能改变产品本体的颜色、数量、形状、接口、材质、尺寸或包装内容。生成图要保存提示词、模型、时间、输入资产、版权/授权来源和审核记录。
10. 开发环境不得连接生产店铺并真实上架、调价、停售、采购或付款。生产写入必须在用户明确提供沙箱/生产授权并批准试运行后开启。

## 3. 范围与非目标

### 3.1 MVP 必须完成的闭环

配置与证据 → 候选收集/导入 → 去重与规格归一 → 硬门槛 → 竞品对比 → 供应商映射 → 完全成本与定价 → AI 内容/图片草稿 → 合规校验 → 人工批审 → 官方 API/模板发布 → 回读验证 → 订单同步 → 现金预留 → 采购清单与人工付款 → 国内包裹/云仓/SLS → 结算/提现/银行到账 → 商品利润、月结和 28 天现金预测 → 复盘与停品/优化建议。

### 3.2 MVP 不做

- 未经授权的全站爬取、验证码绕过、网页模拟登录或浏览器机器人上架。
- 自动支付、自动取消订单、自动销毁退件、自动追加预算。
- 用生成式 AI 凭空创造产品事实或把竞品素材改一下就当自有素材。
- 多市场、多店、复杂微服务、昂贵大数据平台。
- 用模拟订单代替真实结算验收，或承诺销量、GMV、月利润必达。

## 4. 推荐技术方案

采用“模块化单体 + 独立任务队列”，优先控制开发和运维成本。未经书面 ADR 说明理由，不要拆成微服务。

- 前端：Next.js + TypeScript + Tailwind CSS + shadcn/ui；支持中文后台、桌面优先、基本移动端查看。
- 后端：Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2 + Alembic。
- 数据库：PostgreSQL；所有财务金额使用 `NUMERIC/Decimal`，严禁二进制浮点参与金额计算。
- 队列：Redis + Celery/Dramatiq/RQ 三选一，以团队熟悉度为准；必须支持幂等、指数退避、限流、暂停、死信和可视化状态。
- 文件：S3 兼容对象存储；保存原始导入、竞品证据快照、授权素材、生成图、采购/物流/结算凭证。
- 观测：结构化日志、错误追踪、任务指标、审计日志；PII 和密钥不得进入日志。
- 部署：Docker Compose 本地与测试环境；生产优先一台低成本主机/托管数据库，保留每日备份和恢复脚本。
- 测试：pytest、前端单元测试、Playwright 关键流程 E2E、费用引擎属性测试/参数化边界测试。
- 仓库：monorepo，至少含 `apps/web`、`apps/api`、`workers`、`packages/contracts`、`docs`、`infra`、`tests/fixtures`。

如果现有仓库已有技术栈，先审计并给出“沿用或迁移”的 ADR，不得为了匹配本建议无理由重写。

## 5. 十二个业务模块

### F01 店铺与费率中心

配置国家、店铺类型、SLS 渠道、店龄、首刊日、活动开关、费率、计费基数、含税状态、封顶、最低费、互斥组、豁免条件、类目、时间范围、来源链接/截图和账单样本。每条规则具备草稿、已核实、已生效、已过期、冲突状态。

### F02 今日工作台

展示候选、待补证、待定价、待内容审核、待发布、发布失败、订单采购、临近交运、现金风险、对账差异。有效上架只统计当日首次成功发布、可售且获得平台商品 ID 的不同 SPU。

### F03 候选与市场分析

支持 CSV/Excel、用户提供链接、自有店铺数据、获许可 API/MCP。保存原始数据、来源能力声明和快照。实现去重、相同规格归一、本地现货与跨境直邮分组、到手价比较、价格带、评价/差评主题、发货地、配送时间和证据置信度。

### F04 供应商与可售数量

维护供应商、主/备货源、实物 SKU、变体映射、MOQ、单件代发、当前报价、可信库存、报价/库存时效、备货 P50/P95、国内运输 P50/P95、包装后尺寸重量、敏感货属性、退换条款、凭证和质量记录。

### F05 成本与定价

逐项展开收入和费用，支持单件、套装、变体、多商品订单、不同支付方式、活动、退款风险、汇率和 14/21/28 天现金场景；输出目标成交价、展示价、折扣底价、最高可接受采购价、基准/压力净利和市场可行性。

### F06 商品内容与批量审核

生成并编辑英文标题、卖点、描述、属性、规格、变体、FAQ、包装清单、使用/兼容提示和图片。右侧显示事实来源、证据、未支持声明、成本和风险。只有校验通过的商品可进入逐条或整批人工批准。

### F07 发布任务中心

发布已批准的内容版本；支持官方 API 或官方批量模板。实现幂等、防重、限流、部分失败单独重试、暂停、令牌失效阻断、平台 ID/链接保存及回读标题、价格、库存、变体和可售状态。

### F08 出单采购台

订单同步后按订单 ID 幂等入库，冻结成交时的规则版本并预留采购/物流/退款资金；重新核实报价、库存、利润和最迟采购时间；生成采购清单，由人确认付款并录入供应商订单号和凭证。

### F09 云仓与发货台

维护国内包裹、到仓、核数、称重、照片、打包、出库、SLS 扫描、多包合单/拆单、问题件、退件和仓储计时。最迟采购时间按平台交运截止倒推；问题件只提醒和升级，不能自动销毁。

### F10 现金与对账

导入平台结算、退款、活动费用、钱包/连连、提现批次、净汇率、银行到账和发票凭证；实现订单—结算—提现—人民币到账的闭环对账，展示预计与实际差异。

### F11 税务与仓储

保存杭州个体户查账档案、年度累计收入/成本/损失/预缴税、适用税率和优惠版本；仓储类型和 7 天/1 月/3 月等起算规则独立。模块只提供可追溯的经营估算和资料清单，不替代税务专业意见。

### F12 复盘与迭代

按 SPU、类目、供应商、来源、价格带、上架批次分析曝光、点击、加购、成交、退款、履约和实际净利；建议“补证、改内容、提价、降价、停品、换供应商”，每条建议必须带数据依据、预期影响和人工确认边界。

## 6. 选品引擎

### 6.1 数据源适配层

定义统一 `MarketDataAdapter`，Sorftime MCP 和后续数据源只实现适配器，不侵入核心业务。每个适配器必须声明：

- 来源 ID、许可/授权范围、数据所有者、支持市场和类目；
- 能力：关键词、商品、排名、销量时间窗、评价、广告标记、店铺信息等；
- 字段语义和单位；累计值与时间窗值必须区分；
- 请求限制、费用、缓存时长、数据延迟、缺失规则；
- 原始响应保存策略、快照哈希、观测时间和可信度；
- 不可用时的降级方案：文件导入、人工录入或明确“未知”。

禁止把“累计已售”改名为“近 30 天销量”，禁止把搜索样本当成全市场。自有店铺接口权限与全站市场数据权限必须分开显示。

### 6.2 标准流程

1. 定时/手动采集候选，记录来源。
2. 按供应商商品 ID、指纹、图片感知哈希、标准化标题和关键规格去重。
3. 规格归一：数量、尺寸、重量、材质、适配型号、套装内容、变体。
4. 执行硬门槛。
5. 采集同规格竞品，默认目标 10–20 个；不足时显示样本不足，不得伪造。
6. 分组比较菲律宾本地现货与跨境直邮的到手价、配送时间、评价和差评主题。
7. 供应商与物流复核。
8. 成本反推与市场价格带可行性检查。
9. 对通过项评分、生成可解释排序和每日 shortlist。
10. 生成内容草稿并进入人工审核。

### 6.3 硬门槛

- 不是禁限售、高风险资质未知、明显侵权或无合法素材来源商品。
- 有真实可采购 SKU；关键规格可映射；供应商报价和库存未过期。
- 包装后尺寸重量与敏感货属性已核实，SLS/云仓可承运。
- 最迟采购/交运时间可满足。
- 基准完全成本净利率 ≥20%，净利润为正；所有变体和主推套装分别通过。
- 市场可接受价不低于目标成交价；若只能靠虚假大折扣或错误规格进入价格带则拒绝。
- 现金预留后不突破资金池和应急保护线。

### 6.4 评分

总分 100：需求证据 20、竞争空间 15、完全成本与利润 25、供货履约 20、现金占用 10、售后与内容 10。权重必须可配置和版本化。

- `>=75`：优先人工审核；
- `60–74`：补证；
- `<60`：暂缓；
- 任一硬门槛失败：拒绝，不能被总分抵消。

输出必须包含每项子分、计算输入、证据、置信度、淘汰原因和下一步补证动作。

## 7. 供应商体系

供应商不能只有一个“评分”字段。建立以下可解释维度：价格竞争力、报价稳定、库存可信度、备货 P95、按时发货率、样品一致性、错漏率、退换处理、凭证完整、沟通时效、单件代发能力、包装质量、敏感货申报、备用货源覆盖。

同时实现：

- 主供应商与已验证备用供应商；变体逐一映射，不能只映射 SPU。
- 报价和库存 TTL；初始 24 小时只是可改假设，高波动商品更短。
- 报价变更触发重新定价；利润跌破 20% 自动阻断新采购并进入人工异常。
- 可售数量 = 可信可供数量、资金可承受数量、当日履约能力和平台限制中的最小值；禁止无限库存。
- 无证据的供应商自报库存不能当成自有库存。
- 未经批准不得因断货替换颜色、规格、功能、材质或降低质量。

## 8. 费用与定价引擎

### 8.1 收入和完全成本口径

保留 PHP 原币与 CNY 折算。汇率定义为 `e = 1 PHP 实得多少 CNY`，同时保存报价来源、时间和 PHP→结算币→CNY 链路。

商品净收入 `R`：商品售价 − 卖家折扣/卖家券 + 确认可归属卖家的平台商品补贴 − 退款 − 不属于收入的代收税款。买家运费、物流补贴和物流扣款单列，以免混入商品销售规模。

完全成本至少包括：

- 采购成本；
- 国内采购运费；
- 云仓套餐、不同 SKU 附加、包材、检测、超重、超规；
- SLS 卖家实际承担运费、附加费、退件费，减已确认的物流补偿；
- 平台交易、佣金、订单处理/基础设施、卖家增长、活动、跨境等费用；
- 广告与卖家承担的营销成本；
- 正常、拒收、未送达、退款不退货、退货、重发等互斥结果的期望损失；
- 收款、提现、固定/最低费、银行费和汇兑点差；
- 仓储、退件和售后库存；
- 合理固定运营费分摊；
- 版本化税费预计、应计、预缴、可抵免和最终申报调整。

净利润：`N = R + 已确认物流净补偿 − 全部实际归属成本`。

净利率：`M = N / R`。若 `R <= 0`，返回“不可判定/亏损”，禁止除零。

### 8.2 费用规则模型

每个 `FeeRuleVersion` 至少支持：店铺/国家/类目/卖家类型、费项 ID、名称、币种、计费基数表达式、百分比、固定费、最低费、封顶、按订单/商品/件/SKU 粒度、阶梯、互斥组、活动开关、豁免资格、含税标志、舍入层级、起止日、证据和核实状态。

当前可作为测试种子的证据，但不能当永久常量：

- Linear 中卖家截图值：佣金 12%、平台运费 5.6% 且疑似每件封顶 PHP100、普通交易 2.24%、特定分期 5.24%–8.24%、订单固定费 PHP5、卖家增长 1%–1.5%、MDV 4%、Live Xtra 3.36% 等。除普通交易费外，多项仍需用本店 2026 年账单和后台规则核实。
- 截至 2026-09-08 的 Shopee 菲律宾官方条款写明：普通 Transaction Fee 为 2.24%；Order Processing Fee 为每个成功订单 PHP5，且每月前 50 个成功订单豁免；类目佣金和 Seller Growth Support Fee 使用类目费率，后者自 2026-05-11 起实施并通常在首次上架 90 天后开始；菲律宾境外卖家另有按通知费率计算的 Cross Border Fee。实现时必须将这些做成带证据日期的规则，并以卖家后台/结算明细校准。
- 表示“含 VAT”的平台费不得再次统一加 12%。
- 普通交易费与实际适用的分期费按支付方式互斥，不能叠加。
- CCB 若已并入其他费项不得重复计费；活动费只在实际参加期间启用。

### 8.3 云仓测试种子

保存为“待合同核实”的报价版本：套餐 A 为 CNY2.5/单含 1 种 SKU、每多 1 种 +0.5；套餐 B 为 CNY3/单含 3 种 SKU、额外每种 +0.5；同一 SKU 多件仍算一种。体积、超重、仓储、退件等规则必须独立，冲突报价不得自动选一个当真值。

### 8.4 反推价格

目标是求允许价格步长上的最小成交价 `P`，使：

- `M(P) >= 20%`；
- `N(P) > 0`；
- 所有报价、运费、费率和汇率均在有效期；
- 所有变体和主推套装通过；
- 目标成交价不超过可解释的市场价格上限；
- 现金占用不突破资金规则。

因为存在固定费、封顶、阶梯、互斥、活动和年度税负，默认使用逐项费用引擎在合法价格区间上单调搜索/离散搜索；按 Shopee 允许的价格精度向上取整，再完整重算。只有在所有费率同基数、无线性之外的规则且固定成本明确时，才可展示教学公式 `P = C / (1 - 比例费率 - 目标净利率)`；分母小于等于 0 时返回“结构不可行”。

展示价与计划折扣分离：先求目标成交价，再根据卖家折扣计算展示价，最终按实际成交价重算，不允许用虚假原价掩盖不盈利。

### 8.5 多商品与风险

- 订单固定费只收一次，再按净收入占比分配；物流按计费重量分配；商品自身费用直接归属；分配后商品利润之和必须等于订单利润。
- 提现固定费按提现批次分配，不能每件重复收取。
- 风险场景必须互斥，概率总和为 100%。分别计算每个结果的收入、不可退费用、残值和重发成本，再加权。
- 至少输出基准、采购 +10%、物流 +15%、PHP 贬值 5%、高档分期费和组合压力情景。幅度可配置并版本化。

## 9. 资金控制

固定建立七个资金池：样品与验证 1,500；首轮出单采购预留 5,000；国内物流/云仓/SLS 垫付 3,000；测试推广 2,000；工具与运营 1,000；滚动采购缓冲 2,500；应急保留 5,000；合计 20,000 CNY。

应急保留默认不可用于新增采购承诺。资金“划拨、预留、实际支付、释放、退款、损失”必须分开记账。

系统逐日预测未来 28 天：订单量、单件现金垫付、采购提前期、平台结算、提现、退款和广告支出。必须复现示例：15 单/日 × 25 CNY/单 × 14/21/28 天 = 5,250/7,875/10,500 CNY，仅采购占资就在 21 天情景超过 7,500 元采购池，因此要预警而不是依据总资产盲目放量。

可用现金 = 银行可用余额 − 已承诺采购 − 已承诺物流 − 退款准备 − 税款准备 − 受保护资金。平台待结算、待提现余额单独展示。

月目标反推必须支持：在最终单件净利 10/15/20/25 CNY 情景下，月成交至少 501/334/251/201 件才会超过 5,000 元；继续反推所需流量、转化率、日订单和资金峰值，但明确这不是销售保证。

## 10. AI 商品事实、卖点和图片流水线

### 10.1 事实优先

先生成 `ProductFactSheet`，再生成文案和图片。每个事实包含字段、值、单位、适用变体、来源资产/页面、原文、置信度、审核状态。建立 `ClaimLedger`：支持、待核实、禁止使用。任何营销声明必须引用已支持事实。

### 10.2 文案输出

针对菲律宾市场生成：

- 英文标题草稿，包含核心品名、关键规格、主要用途；避免商标滥用、关键词堆砌、夸大词和无证据“best/no.1/100%”。
- 3–5 个可验证卖点，每条附事实来源。
- 结构化描述：适用场景、关键规格、尺寸/单位、材质、兼容性、包装清单、使用/清洁/安全提示、跨境配送预期和售后边界。
- 变体表、尺寸转换、FAQ、搜索关键词建议。
- 可选 Tagalog 短卖点，但不得牺牲准确性；无法可靠翻译的技术词保留英文。

### 10.3 图片处理

资产状态：原始供应商授权图、卖家自有图、可商用素材、AI 生成背景、平台成品图。每个资产保存许可证/授权凭证、来源 URL、哈希、使用范围和到期日。

建议图片组：

1. 主图：真实产品、干净背景、无误导配件；
2. 卖点图：一个事实一个重点；
3. 尺寸/规格图：统一单位且与变体一致；
4. 使用场景图：可以生成背景，但产品本体必须来自真实素材并保持准确；
5. 包装清单/兼容性图；
6. 注意事项/细节图。

图片管线：授权检查 → 去重 → 裁切/抠图/色彩校正 → AI 背景/场景生成 → 模板排版 → OCR 校验 → 产品一致性检查 → 平台尺寸/大小检查 → 人工预览 → 批准。若 AI 无法保持产品本体准确，禁止发布并改用真实图或标明示意图。

图像生成提供商必须通过 `ImageGenerationAdapter` 抽象；保存输入、提示词、负面约束、模型版本、输出、人工审核和成本。供应商/竞品图未经权利确认时不能送入外部模型或发布。

## 11. 发布与订单状态机

### 11.1 商品版本状态

`NEW → ENRICHING → NEEDS_EVIDENCE / HARD_REJECTED → SCORED → CONTENT_DRAFT → VALIDATED → PENDING_APPROVAL → APPROVED → QUEUED → PUBLISHING → PUBLISHED_UNVERIFIED → PUBLISHED_VERIFIED`

异常分支：`FAILED_RETRYABLE`、`FAILED_FINAL`、`PAUSED_AUTH`、`STALE_APPROVAL`、`DELIST_REVIEW`。

只有 `APPROVED` 的不可变版本可发布。报价、重量、库存、费率、汇率、素材、标题、价格、变体或合规状态变化时转为 `STALE_APPROVAL`。

### 11.2 订单与履约状态

`RECEIVED → FUNDS_RESERVED → SUPPLY_RECHECKED → PURCHASE_APPROVAL → PURCHASED → DOMESTIC_IN_TRANSIT → WAREHOUSE_RECEIVED → PACKED → SLS_HANDOFF → DELIVERED/RETURNED → SETTLED → RECONCILED`

任一阶段可进入 `EXCEPTION`，保存责任人、截止时间、原因和处置。重复 webhook 不得重复预留、采购或建包裹。

最迟采购时间：`平台最迟交运时间 − 供应商备货P95 − 国内运输P95 − 云仓处理/班车等待 − 安全缓冲`。

## 13. 连接器契约

至少定义并以 mock 实现：

- `ShopeeConnector`：授权能力探测、类目/属性、图片、发布、更新价格库存、读取商品、订单/webhook、物流状态、结算；不可用能力返回明确 `UNSUPPORTED`，禁止假成功。
- `MarketDataAdapter`：候选、关键词、竞品和时间窗指标；Sorftime MCP 未来按此接入。
- `SupplierAdapter`：报价、库存、SKU、采购单导出/回填。
- `WarehouseAdapter`：入库预报、称重、包裹、异常、出库；无 API 时用版本化 CSV/Excel。
- `PaymentAdapter`：钱包/连连报价、提现批次和到账回填；第一版不得自动发起不可逆支付。
- `ImageGenerationAdapter`：生成、编辑、用量和内容凭证。

所有外部调用实现超时、限流、签名验证、重试分类、幂等键、死信、脱敏日志和能力矩阵。授权失效时暂停写入并提示重新授权，不切换到网页机器人。

## 14. 页面与交互要求

- 左侧为 F01–F12；中央为可筛选、锁列、保存视图、批量操作的表格；右侧抽屉显示商品证据、成本明细、风险、版本和审核历史。
- PHP/CNY 同屏显示，明确汇率方向、时间和预计/实际标签。
- 状态同时使用文字、图标和颜色，不只靠颜色。
- 每个阻断项提供“缺什么、由谁补、如何补、截止时间”。
- 所有批量操作先显示影响数量、资金、价格、预计利润和失败项；发布前显示最终差异预览。
- 对调价、停售、采购、取消、销毁、追加预算等关键动作提供二次确认和审计日志。

## 15. 权限、安全与可靠性

- 角色：店主、运营、财务/审计、只读、自动化服务；店主批准关键操作。
- API 凭证仅服务端加密保存，前端永不回显完整密钥；优先外部密钥管理或系统密钥引用。
- 客户地址、电话等只保存履约所需最少字段，日志和分析数据脱敏；定义保留期限和删除流程。
- 财务规则、审批和发布记录使用不可变审计事件。
- 任务支持 exactly-once 业务效果（通过幂等和数据库约束实现，不宣称网络层绝对 exactly-once）。
- 数据库每日备份；W7 必须实际做一次恢复演练并记录恢复点和耗时。
- 所有时间以 UTC 存储，界面显示 Asia/Manila/Asia/Shanghai；两地当前同为 UTC+8 也不要省略时区。
- 任何未知费率、权限或来源过期都要安全失败，不得静默使用旧值继续发布。

## 16. 关键验收用例

费用引擎必须用自动化测试覆盖：

1. PHP500、共同基数测试：佣金 12%=60、平台运费 5.6%=28、普通交易 2.24%=11.20、增长 1.5%=7.50、固定费 5，合计 111.70 PHP；含税费项不再加 12%。仅作为种子规则测试，不代表最终实际账单。
2. 同单切为高档分期 8.24%：分期费 41.20，普通 11.20 必须移除；上述假设下总费 141.70。
3. 平台运费基数 3000 PHP、单件：5.6%=168；如果核实为按件封顶则取 100；两件的封顶粒度需按规则分别计算。
4. 云仓套餐 A，1 种 SKU×10 件仍为基础 2.5 CNY；2 种 SKU 为 3.0 CNY。平台订单固定费仍只收一次。
5. 一个提现批次含 100 个订单，固定手续费 10 CNY；分配合计必须为 10，不是 1000。
6. 零散包裹第 8 天进入异常，不能误用备货 3 个月免费期。
7. 商品净收入 100 CNY、全部成本 80 CNY时净利 20、净利率 20%；若 80 只是采购价且其他成本未知，必须阻断达标结论。
8. 多商品分摊、退款回冲、跨月仓储、平台补贴和税费调整后，商品合计与订单/月总账一致，舍入尾差可追踪。
9. 重复订单 webhook 不产生第二次资金预留或采购单。
10. 发布超时但平台实际成功，再次重试时通过幂等/回读避免重复链接。
11. 部分变体发布成功时只重试失败变体/任务，最终回读价格、库存和状态。
12. 供应商涨价导致净利率 19.99%、库存过期、重量缺失、图权未知或 SLS 时限不足时均阻断。
13. 订单固定费每月前 50 单豁免与非豁免边界必须根据版本化规则测试，不能写死在代码分支。
14. 14/21/28 天现金情景、跨月退款、平台先结算但银行后到账、两个收款通道只选择真实路径。
15. 至少 5 种真实费用结构的订单由人逐笔对账；真实数据未到时标记“待验收”，不能用合成数据宣告完成。

## 19. Definition of Done

只有同时满足以下条件，MVP 才可声明完成：

- R00–R15 的 P0 功能完成，或有用户明确接受的保留项；
- 费用和定价引擎通过全部边界测试，金额无浮点误差；
- 未知关键数据会阻断，不会默认 0；
- 发布、订单和采购具有幂等性，断网/超时/部分成功不会重复操作；
- 审批和版本失效逻辑有效；
- 从候选到发布，再到订单、采购、包裹、结算、人民币到账可追溯；
- 完成备份恢复演练、安全检查和关键权限测试；
- 3–5 款小量试运行通过后，连续 5 个运营日能处理 10–20 个合格 SPU/日；
- 至少 5 笔不同费用情形的真实订单完成逐笔人工对账，未自然完成的真实回款明确保留；
- 系统不承诺销量或利润，但能准确显示达成月净利目标所需的成交、流量和现金条件。
