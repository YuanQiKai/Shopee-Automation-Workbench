# Meeya · Shopee 菲律宾选品工作台

本地原型 v0.4，面向 2 万元启动资金、每天 2–3 小时、出单采购不囤货的菲律宾跨境卖家。新增七维上架测试门槛、证据时效、组合压力测试及 28 天资金核验；保留真实接口调研、分页、候选自动保存和旧版数据。

## v0.4 上架判定入口

打开“调研与选品 → 上架判定规则”查看完整标准；在“候选决策”第 2 节填写逐竞品销量窗口，第 6 节填写七维证据。系统显示通过、不通过或待补证及原因。全部必选项和资金检查通过才可进入人工上架测试审核，复购扩展为可选加分。详细口径见 [七维选品规则](SELECTION-RULES-v0.4.md)。

当前任务的每日调研已设为北京时间 **20:00**，目标至少 10 个不同产品候选；证据不完整时如实报告缺口，不降低门槛。调度由当前 Codex 任务维护，网页本身没有后台定时器。真实店铺发布仍未连接。

真实商品进入旧版内容包审核时，必须关联已通过的新候选研究，并保持名称、采购 SKU、价格、支付、重量和成本一致；证据过期、草稿未完成、费用或规则变化均会使旧审核失效。旧版六维手工评分不能覆盖此检查。

**已经实现：候选录入 → 供应商复核 → 完全成本试算与双目标定价 → 英文事实文案 → 原图排版 → 内部审核 → 通用内容包导出。**

这是单机原型，不是无人值守生产系统。没有连接真实店铺，不会采购、发布或投放广告。Sorftime 查询可能消耗你已有账号的额度；本轮不购买服务或充值。详细范围与待补资料见 [本次交付说明](RESEARCH-v0.3.md)；[v0.2 说明](RESEARCH-v0.2.md)保留作历史记录。

## v0.3 先从这里体验

1. 打开首页“调研与选品”。商品成交价上限按你确认的 **1,000 PHP** 初始化，可在页首修改；修改会重新判断已有候选。这个经营上限与具体商品的“同规格市场价格上限”不同。
2. 首批范围为家居用品。化学、带电、易燃易爆、复杂认证及额外认证成本商品是硬性排除项；尚未核实的商品不会自动通过。搜索命中并不等于符合范围。
3. 在“连接与采集记录”输入 Sorftime 密钥，再点“验证并连接”。**不要发到聊天、不写进源码**。密钥只留在本机服务进程内，输入框提交后清空，重启后需重填。也支持由启动环境提供 `SORFTIME_MCP_KEY`；请勿把它写入仓库或启动脚本。
4. 市场页和货源页可选择多条件接口，填写的条件直接发送 Sorftime；关键词检索需要切换对应接口，不在多条件接口虚构关键词参数。每次只查询指定接口页；“读取详情与 SKU”会执行两次查询。结果自动按 10/20/50/100 条显示分页，默认 20 条，表格区域固定为 20 行高度，超出滚动。翻显示页不请求接口、不额外计费。接口总页数不等于已经下载的数据量。
5. 从 Shopee 样本点“研究此款”。研究中的报价、费用、规格、重量和证据初始为空。添加竞品、选择真实 1688 商品及其 SKU，核实可下单条件，再逐项填入成本、来源和有效期。
6. 候选输入后自动保存，切换标签、候选和主菜单都会先提交草稿，无需手动点保存。“立即核验”只用于立即触发保存与检查。没有填完或暂时非法的数字也能保存为草稿，不会以旧利润冒充当前结果；断网会显式提示并在本机暂存，版本冲突会另存副本。恢复操作在“连接与采集记录”。
7. 点击商品图片或“详情 / 全字段”查看完整标题、所有原图、原始字段、字段说明、请求参数及数据检查。全部 22 项接口可在“全部接口与返回参数”操作；类目、趋势、店铺、关键词、嵌套对象和未知新字段均可展开，完整 MCP JSON 不裁剪。
8. 22 项中 19 项为数据查询，另外 3 项会新增/移动/删除 Sorftime 关键词收藏，必须逐次确认，不在后台自动执行。Shopee 站点固定 PH；失败、限流、无权限会明确记录，不用旧缓存冒充新结果。

本次验收时本机共有 263 条真实来源观测，去重为 40 个 Shopee 商品、149 个 1688 货源商品、1 个 SKU；另保留类目和非商品原始响应。对话 MCP 采集与本机后端 MCP 查询分开标注。这些是调研和接口验证样本，不是选品推荐，也不等于已经完成同款采购匹配。源码包不包含业务数据库、业务图片或这些快照。

有效期需输入明确时区，例如 `2026-09-10T18:00:00+08:00`，但必须以凭证实际有效期为准，不能直接照抄示例。手动勾选仅代表操作者声明，不代表系统鉴定了文件真伪。

## 打开与重启

1. Windows 双击本文件夹的 `start.cmd`，保持终端窗口运行。
2. 浏览器打开 <http://127.0.0.1:8765>。
3. 停止服务时，在该终端按 `Ctrl+C`。重新启动后保留已有数据。

若当前服务已经运行，不必重复启动。端口被其他程序占用时，可在本文件夹运行 `start.cmd --port 8766`，并打开对应端口。

其他具备 Python 3.11+ 的电脑可运行：

```sh
python server.py
```

不需要安装第三方 Python 包。离线查看/导入/核算不需要 API Key；发起真实 Sorftime 查询需要你的账号密钥并可能消耗额度。不提供公网访问、用户账户或生产安全保障，请勿修改为公网监听。本次继续沿用已有本机架构，没有把业务数据发布到网上。

## 旧版演示路径（与真实调研独立）

1. 在“选品池”中找到“抽屉分隔收纳盒”，点击“核算”。
2. 在“定价实验室”修改采购成本或售价，查看费用明细、单件净利、净利率和最低整数 PHP 成交价。最低价同时满足两个利润目标，不等同于推荐市场价。点击“保存成本与价格”后才会持久化。
3. 点击“前往商品内容”，再点击“整理英文文案”。模板只组合已录入的英文事实，可编辑保存。
4. 可选：上传自己拥有使用权的 PNG/JPEG/WebP 原图（≤ 4 MB），下载 1200 × 1200 原图排版图。保持原图比例，不抠图，不改变产品，不调用 AI。图片单独下载。
5. 点击“审核示例内容”并确认，然后“导出已审核”。得到 ZIP 文件，含通用 CSV、JSON、费用配置、英文文案和图片提示词。
6. 再修改成本、供应商或费率：旧审核自动失效，必须重新检查后才能再次导出。

初始 8 个商品和 3 个供应商全部虚构，仅用于演示，不是选品推荐或真实调研结果。示例报价初始化后 24 小时到期；到期会阻断审核。试用时可在“完整商品资料”中更新示例有效期，但真实商品必须以真实报价为准。原型不会悄悄延长报价有效期。

录入真实商品时，请先新增真实供应商，不能把示例供应商当作真实供货来源；在“费率与接入”中依据本店实际资料核实费率。没有资料的成本留空，不要为了通过检查填 0。

## 定价口径与限制

- 单件、单订单、商品成交价模型；输入的是折扣后成交价，不是划线原价。
- 成交收入 = 商品成交价 PHP × PHP→CNY 汇率。买家运费仅进入本原型交易费基数，不重复计商品收入。
- 净利 = 成交收入 − 所有录入及计算成本；净利率 = 净利 ÷ 成交收入。税费、售后、固定开支为手动分摊暂估，因此结果是试算，不是已实现财务净利润。
- 使用 Python `Decimal` 计算。每项 CNY 成本四舍五入到分；比例费先在 PHP 四舍五入到分，再换算 CNY 到分。显示的成本明细可以加总核对。
- 普通交易费与分期费互斥；平台运费设单件封顶；订单固定费在本模型只计一次，可在情景中豁免。
- 反推范围为 1–100,000 整数 PHP。按封顶费率分段缩小搜索区间，再逐价精确验证，兼顾舍入边界。最低可行价必须同时达到净利率与单件利润目标；超出市场上限会阻断审核。
- 成本缺失、报价过期、供货异常、时限不足、缺少 SKU/包装重量/复核证据会阻断。真实商品还需人工核实费率且关联真实供应商。
- 当前费率是历史种子和演示假设，不是最新官方费率。特别是 **SLS 卖家净物流与平台运费是否重复、收费基数、收款费率、税务、补贴归属**，必须用本店适用资料确认。若不适用，明确记录依据后将对应费用设为 0。
- 手动勾选“已核实”代表操作者的声明，不代表系统已检查外部文件，也不构成税务或平台合规认证。
- 不支持当前规则之外的阶梯费率、批次提现实际核算、多件购物车、优惠券分摊、退款事件、订单税务结算。

## 资金口径

初始规划：样品 1,500、首轮采购 5,000、物流 3,000、推广 2,000、工具 1,000、滚动采购 2,500、应急 5,000，合计 CNY 20,000。

资金池是初始规划，不是银行子账户或真实账本；本版不支持编辑七池额度。余额、已承诺支出、保护资金、订单假设等可以修改保存。

采购占资 = 假设日订单量 × 单件采购垫付 × 周转天数。初始 15 单、25 元、14/21/28 天对应 5,250/7,875/10,500 元，与 7,500 元采购池比较。这里只算采购垫付，**不代表已覆盖全部现金流**。

## 数据保存与导出

- 本机数据库：`data/meeya.sqlite3`，首次启动自动创建。图片、商品、供应商、规则、审核、导出索引和审计日志都存储在此。
- 页面右上角和配置页可下载 JSON 快照（含图片和审计记录）；本版没有 JSON 一键恢复入口。
- 需要可直接恢复的备份时：先停止服务，再复制整个 `data` 文件夹到安全位置。恢复前先保留当前文件夹副本，不要直接覆盖唯一原件。
- ZIP 内容包 **不是 Shopee 官方批量模板，不能直接导入并宣称上架成功**。内容图目前单独下载，不含在 ZIP 中；原图包含在 JSON 备份中。
- 审核绑定商品、供应商、全局配置版本。即使仅修改资金情景，当前保守实现也会使旧审核失效。
- 相同产品版本重复导出复用同一导出记录；修改后不能沿用旧审核。历史列表的“再次下载”会重新验证当前版本，不是不可变历史归档。
- 记录保存最新业务版本号和操作日志，尚未保存每次变更的完整历史快照。
- 不要把包含供应商、报价和图片的 `data` 或 JSON 备份推送到公开仓库。

## 实现与技术决策

当前实现为静态 HTML/CSS/JavaScript + Python 标准库 HTTP 服务 + SQLite，服务仅监听 `127.0.0.1`。

原计划使用 Sites 的前端与数据库脚手架；固定版本初始化器在本环境遇到 `@clack/prompts` 依赖缺失，未生成可用项目。因此本轮为可交付性采用零第三方运行依赖的本地方案，没有创建 Sites 项目或发布地址。这是 MVP 技术裁剪，不是主开发 Prompt 中完整生产架构已落地。

目录：

```text
mvp/
  server.py        HTTP / 持久化 / 审核 / 导出
  engine.py        Decimal 定价与阻断检查
  research.py      原始证据 / 归一化 / 候选判断 / 经营上限
  sorftime.py      MCP 连接器；关键词收藏修改需逐次确认
  sorftime_catalog.json  已发现的 22 项工具与完整参数基线
  import_research.py  快照导入 / 导入前 SQLite 备份
  seed.py          明确标记的虚构种子
  static/          8 个主页面（调研页含 6 个工作区）
  test_mvp.py      26 项计算与 HTTP 集成回归
  test_research.py 调研与连接器回归，全部为隔离的合成测试数据
  test_research_v03.py  全接口契约 / 自动保存 / 新响应结构回归
  test_research_ui.cjs  分页 / 完整字段 / 自动保存交互逻辑检查
  test_ui.cjs      Node VM 页面渲染函数检查（不代替浏览器测试）
  start.cmd        Windows 启动入口
  data/            运行数据，不打包、不进版本控制
```

API 接口边界：`GET /api/state`、`POST /api/pricing`、`POST /api/products`、`POST /api/products/{id}`、`POST /api/products/{id}/content`、`POST /api/products/{id}/approve`、`POST /api/suppliers`、`POST /api/settings`、`POST /api/assets`、`POST /api/export`、`GET /api/backup`。

修改接口要求页面会话令牌；后台检查 Origin/Host 与记录版本号，避免跨站写入和旧页面覆盖新记录。本版不是多用户认证系统，仍不可放到公网。

## 后续最小迭代顺序

1. 用 3–5 个真实商品和本店账单校准费用、物流与收款模型；补齐 SKU 级供货证据和尺寸重量。
2. 升级重启后在本机重新输入密钥，核对账号实际工具权限；向数据方确认 PH 价格字段说明与返回值的币种冲突，再根据真实凭证开展决策。CSV 不是本版输入格式，支持保留原始 MCP 响应的 JSON 导入。
3. 接一个可替换的 AI 提供商：替换事实整理与图片生成服务，设置单日预算/单品费用、素材授权、生成审核和失败重试；不得在前端保存密钥。
4. 获得 Shopee 开发者权限后接类目属性与草稿创建，先 dry-run + 人工确认，再考虑发布；保存请求幂等键和官方回读结果，只有确认 item_id 与上架状态才计入真实上架。
5. 通过样品、订单和回款测试后，再做自动采购、云仓履约、结算与无人值守队列。

是否达到日均 10–20 款，必须在真实数据、费用凭证和审批流程接入后单独验收。本版不声称已实现完整自动选品、自动询价、自动生图或自动上架。
